# RetailOps Kiosk

RetailOps Kiosk is a standalone self-checkout Progressive Web App for the
RetailOps Backend API. It runs as static HTML, CSS, and vanilla JavaScript: no
build step, no bundler, no npm install.

The kiosk connects to a RetailOps Backend station using a per-station
`KioskKey`. Customers can identify/register themselves, scan or search products,
build a cart, choose a payment method, and submit an atomic checkout through the
backend kiosk API.

## Quick Install

Linux/macOS:

```bash
curl -fsSL https://raw.githubusercontent.com/jp72924/retailops-kiosk/main/install.sh | bash
```

Non-interactive install:

```bash
curl -fsSL https://raw.githubusercontent.com/jp72924/retailops-kiosk/main/install.sh | bash -s -- \
  --backend-url http://127.0.0.1:8000 \
  --api-key <KIOSK_API_KEY> \
  --store-name "RetailOps Kiosk" \
  --store-address "Local store" \
  --station 1
```

Windows PowerShell:

```powershell
irm https://raw.githubusercontent.com/jp72924/retailops-kiosk/main/install.ps1 | iex
```

After installation, open:

```text
http://127.0.0.1:8080/
```

## Developer Setup

```bash
git clone https://github.com/jp72924/retailops-kiosk.git
cd retailops-kiosk
cp config.example.js config.local.js
python3 -m http.server 8080
```

Open `http://127.0.0.1:8080/`.

Edit `config.local.js` with the backend URL and station API key generated by
RetailOps Backend:

```bash
python manage.py provision_kiosk --store DEV-LOCAL --station 1 --by admin@example.com
```

## Important Notes

- RetailOps Kiosk does not include the RetailOps Backend.
- RetailOps Kiosk never connects directly to a database or object storage.
- `config.local.js` contains the station API key and must not be committed.
- The app must be served over HTTP or HTTPS. Opening `index.html` with
  `file://` is not supported because ES modules and the PWA service worker need
  an HTTP origin.
